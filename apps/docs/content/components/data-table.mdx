O preview é um `DataTableViews`: cada aba (Transações, Faturas, Transferências, Rendimentos, Gráfico) é uma tabela própria, com colunas e uma "API" de mentira própria (atraso curto, AbortSignal). A primeira abertura de cada aba mostra o carregamento. Todo campo é editável: clique numa célula pra editar. Nas de texto/número, `Enter` confirma e `Escape` desiste; nas de select e status, clique numa opção da lista (ou fora, pra fechar sem mudar o valor único); na de data, o calendário abre e fecha sozinho ao escolher um dia; a caixa marca com um clique. No Tipo e na Meta (relações), o texto edita e o glifo à esquerda abre. No Saldo (fórmula), digitar grava um valor manual e apagar volta ao calculado. Passe o mouse na Descrição pra ver o botão **Abrir**, que abre o painel lateral da linha (propriedades, anterior/próxima, notas). O cabeçalho de cada coluna abre o menu (renomear, ordenar, filtrar, agrupar, congelar, mover, ocultar), arrastar o cabeçalho reordena e o **+** no fim cria uma propriedade. No seletor de Tags, digite um nome que não existe pra criar a opção. Marque linhas pra ver a barra de seleção (Marcar conferidas, Status: Sincronizado, Duplicar, Excluir). O botão de propriedades (controles deslizantes) agrupa as linhas e liga/desliga a quebra de texto, e cada célula do rodapé escolhe o cálculo. Estreite a página: abaixo de 610 de largura do container, a grade vira lista de cartões.

## Como usar

```bash
bun add @adinkra/data-table
```

O exemplo mínimo continua o mesmo de antes — só colunas, linhas e `onRowsChange`:

```tsx
import { DataTable, type DataTableColumn, type DataTableRow } from "@adinkra/data-table";
import { useState } from "react";

const columns: DataTableColumn[] = [
  { id: "descricao", header: "Descrição", type: "text" },

    options: [
      { value: "entrada", label: "Entrada", color: "tag-sky" },

    ],
  },
  { id: "valor", header: "Valor", type: "number", currency: true },
```

## Visual

A tabela é plana (desenho de 07/10): sem cartão em volta, linhas e colunas de 1px `--hairline`, abas só em texto, ferramentas de 26 sem borda (ligadas ficam em `--link`), chips de raio 13 (completos em céu a 21%, incompletos só com contorno), menus no `--card` sem borda e com sombra suave, caixa de seleção nativa. Só a célula sob o ponteiro ganha o véu de hover; menu aberto e edição usam um anel interno de 2px `--ring`. Linha de 42, cabeçalho de 34, texto 13/21 (escala φ).

## Tipos de coluna

Todo cabeçalho mostra o ícone do tipo (13px): Aa, #, Σ, calendário, etiqueta, relação ↗, status, caixa.

- **`text`** — texto livre. A primeira coluna de texto (ou a marcada com `primary`) é a **principal**: ícone de página, texto em seminegrito, botão Abrir no hover (com `onOpenRow`) e título do cartão no mobile.
- **`select`** — etiqueta colorida de uma lista (`options`), cores só das que já existem: `primary`, `accent`, `secondary`, `tag-coral`, `tag-sky`, `tag-mustard`, `tag-navy`, `mist` (névoa azul) e `gray` (superfície). Com `multi: true` vira várias etiquetas por célula. `selectStyle: "pill"` (padrão: etiqueta plana, raio 3, sem borda), `"dot"` (ponto de 8 + texto sublinhado, como Conta e Tags no preview) ou `"badge"` (o `@adinkra/badge`, opt-in). O seletor tem busca; com `onColumnsChange`, digitar um nome que não existe oferece **Criar …** (a cor gira pelo ciclo das etiquetas).
- **`status`** — valor único de `options`, com bolinha de 8 na cor do texto (21 de altura, raio cheio, sem borda). Aceita as cores de etiqueta e `destructive`.
- **`number`** — número em mono à direita; com `currency: true` formata como R$ (`Intl.NumberFormat`, pt-BR). Fica sempre na cor neutra: a cor por sinal foi testada e revertida.
- **`formula`** — calculada por `formula: (row) => number | string`, com `format: "currency" | "number"` opcional. Negativo sai em `--destructive`. Só entra em soma/média/mínimo/máximo quando tem `format`. **Editável como sobrescrita manual**: o valor digitado é gravado em `row[column.id]` e, enquanto existir, aparece no lugar do calculado com um anel pequeno na frente (e "valor manual" pro leitor de tela). Apagar o campo grava `undefined` e a fórmula volta a valer. Abrir e sair sem mudar nada não grava. Filtro, ordenação, busca e agregação usam sempre o valor efetivo: o manual quando há, senão o calculado.
- **`date`** — data guardada como `"yyyy-mm-dd"`; o clique abre o `Calendar` do `@adinkra/date-picker`. `dateStyle: "long"` (padrão, "21 de Setembro, 2026") ou `"short"` ("21 set 2026").
- **`relation`** — rótulo da página ligada, sublinhado, com glifo na frente. Editável: com `options`, edita pelo mesmo seletor do select (grava o `value` da opção, mostra o `label`); sem `options`, edita como texto. O link fica no **glifo**: `relation.href(row)` vira `<a>`, `relation.onClick(row)` vira botão, cada um com `aria-label="Abrir …"`. Clicar no texto edita, clicar no glifo abre. Escolhido em vez de "abrir no hover" porque funciona igual no toque e no teclado (dois alvos de Tab). `relation.icon`: `"link"`, `"in"` (entrada, em primary), `"out"` (saída, em destructive), `"calendar"`, `"pie"`, ou uma função `(value, row) => ícone`, que recebe o valor salvo.
- **`checkbox`** — booleano, marca e desmarca com um clique.

## Visões, busca e ações

A barra superior sempre aparece. A prop `views` do `DataTable` são abas sobre **esta** tabela (`@adinkra/tabs`): a tabela só mostra qual está ativa e avisa a troca (`onViewChange`), e quem usa decide o que cada aba muda. Pra abas com dados, colunas ou API diferentes, use o `DataTableViews` (abaixo). À direita ficam as ferramentas de 34 — filtros (mostra/esconde a barra de filtros), ordenação, busca (com `searchable`) e propriedades —, o slot `toolbar` e, com `onAddRow`, o botão **Novo**. A busca filtra as linhas por qualquer coluna, sem diferenciar maiúscula nem acento.

O painel de **propriedades** mostra/oculta colunas (a principal fica sempre), tem "Mostrar todas"/"Ocultar todas", **Agrupar por** e **Quebrar conteúdo das células** (desligado, o texto fica numa linha e corta com reticências).

## Agrupamento

`groupBy` (controlado, com `onGroupByChange`) ou `defaultGroupBy` agrupa as linhas por uma coluna de seleção, status, relação, caixa ou texto — também dá pra escolher no painel de propriedades ou no menu da coluna. Cada grupo tem um cabeçalho com recolher, a pílula do valor, a contagem e o Σ da primeira fórmula numérica (ou do primeiro número). Grupos seguem a ordem das opções; "Sem …" fica por último. Em select `multi`, a linha aparece em cada grupo das suas etiquetas. **Nova página** dentro de um grupo já cria a linha com aquele valor.

## Seleção e painel da linha

Marcar linhas troca a barra de filtros pela **barra de seleção**: a contagem, as ações de `bulkActions`, **Duplicar** (cópia com "(cópia)" no título) e **Excluir**. Cada ação recebe as linhas marcadas e um `patch(values)` que grava os mesmos valores em todas:

```tsx
bulkActions={[
  { id: "conferir", label: "Marcar conferidas", onSelect: (_rows, { patch }) => patch({ conferida: true }) },
]}
```

Sem `onOpenRow`, `peek` (ou `peek={{ notes: "notas" }}`) faz o **Abrir** abrir um painel lateral (`@adinkra/sheet`): título grande, cada propriedade com o mesmo editor da célula, anterior/próxima pelas linhas visíveis, excluir e, com `notes`, um campo de notas gravado em `row[notes]`. Com `onOpenRow`, abrir continua sendo de quem usa.

## Mexer nas colunas

Com `onColumnsChange`, o menu da coluna ganha o campo de nome, o seletor ganha **Criar …** e o cabeçalho ganha um **+** no fim (texto, número, seleção, seleção múltipla, status, data, caixa). A coluna nova já abre o menu dela pra trocar o nome. No `DataTableViews`, sem `onColumnsChange` na visão, essas mudanças ficam numa cópia local das colunas da aba.

## Abas com dados próprios: `DataTableViews`

Quando cada aba é uma tabela diferente (colunas, dados e API próprios), use `DataTableViews`. É o caminho recomendado sempre que as abas não compartilham os mesmos dados. A prop `views` do `DataTable` continua valendo pra abas sobre a mesma tabela.

- **Cada visão é independente**: `columns`, dados e as demais props do `DataTable` (`defaultFilters`, `defaultSorts`, `onAddRow`, `onOpenRow`, `mobileCard`, `toolbar`, `searchable`, `filterable`…). Uma aba que não é tabela usa `render(ctx)`. No preview, o Gráfico lê as linhas de Transações com `ctx.rowsOf("transacoes")` e declara `dependsOn: ["transacoes"]` pra carregá-las mesmo se Transações nunca foi aberta.
- **Três modos de dado por visão**: `source` (API, com cache interno), `rows` + `onRowsChange` (controlado por quem usa) ou nenhum dos dois (estado local, começa vazio).
- **Carga preguiçosa com cache**: a `source` carrega na primeira vez que a aba abre e guarda o resultado. Trocar de aba não recarrega, a não ser com `refetchOnActivate` (no preview, Rendimentos). A carga recebe um `AbortSignal` e é cancelada ao sair da aba, ao recarregar ou ao desmontar.
- **Estado preservado por visão**: cada aba monta na primeira abertura e fica montada, escondida. Filtros, ordenação, busca, larguras e colunas escondidas continuam lá quando você volta.
- **Estados**:
  - carregando: linhas de `@adinkra/skeleton` na altura real de 42 (cartões no mobile);
  - erro de carga: `@adinkra/alert` destructive com **Tentar de novo**;
  - vazio: "Nenhuma linha ainda." ou, quando filtros/busca esconderam tudo, "Nenhuma linha corresponde a esta visão" com **Limpar filtros e busca** (troque com `emptyMessage`).
- **Edição otimista**: a tela muda na hora e cada diferença vai pra API (`onRowChange` com só as chaves alteradas, `onAddRow` com o rascunho, `onDeleteRows` com os ids). Se a API rejeitar, só aquela mudança volta e um alerta explica. Reordenar por arraste é só local.
- **Recarregar**: `ref` com `reload(viewId?)` (padrão: a aba ativa). Escolhido em vez de uma `reloadKey` porque recarregar é um comando, não um estado.
- **Aba ativa**: controlada (`activeView` + `onViewChange`) ou não (`defaultView`).

No preview, **Simular erro na próxima chamada** faz a próxima chamada de qualquer aba falhar. Depois disso, **Recarregar aba** mostra o erro de carga; editar uma célula mostra o desfazer.

```tsx
import { DataTableViews, type DataTableSource, type DataTableViewsHandle } from "@adinkra/data-table";

// Uma fonte por API. `load` recebe o AbortSignal e passa pro fetch.
function restSource(base: string): DataTableSource {
  return {
    async load({ signal }) {
      const res = await fetch(base, { signal });
      if (!res.ok) throw new Error(`Falha ao carregar (${res.status}).`);
      return res.json();
    },
    async onRowChange(row, patch) {
      const res = await fetch(`${base}/${row.id}`, {
        method: "PATCH",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify(patch),
      });
      if (!res.ok) throw new Error("Não deu pra salvar a alteração.");
    },
    async onAddRow(draft) {
      const res = await fetch(base, { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify(draft) });
      if (!res.ok) throw new Error("Não deu pra criar a linha.");
      return res.json(); // a linha salva (com o id do servidor) troca o rascunho
    },
    async onDeleteRows(ids) {
      const res = await fetch(`${base}?ids=${ids.join(",")}`, { method: "DELETE" });
      if (!res.ok) throw new Error("Não deu pra excluir.");
    },
  };
}

const transacoes = restSource("/api/transacoes");
const faturas = restSource("https://faturas.exemplo.com/v1/faturas"); // outra API
const rendimentos = restSource("/api/investimentos/rendimentos");

function Financas() {
  const ref = useRef<DataTableViewsHandle>(null);
  return (
    <DataTableViews
      ref={ref}
      defaultView="transacoes"
      views={[
        { id: "transacoes", label: "Transações", columns: transacaoColumns, source: transacoes, searchable: true },
        { id: "faturas", label: "Faturas", columns: faturaColumns, source: faturas },
        { id: "rendimentos", label: "Rendimentos", columns: rendimentoColumns, source: rendimentos, refetchOnActivate: true },
        {
          id: "grafico",
          label: "Gráfico",
          dependsOn: ["transacoes"],
          render: (ctx) => <MeuGrafico rows={ctx.rowsOf("transacoes") ?? []} />,
        },
      ]}
    />
  );
}
// Depois de salvar em outra tela: ref.current?.reload("faturas")
```

## Filtros e ordenação

Rodam no cliente, sobre `rows`: busca → filtros → ordenação. Editar continua mexendo no array original pelo `id`, então a ordenação nunca reordena `rows`. Com ordenação ativa, a alça de arrastar some.

- **Barra de filtros** abaixo da barra superior: o chip-resumo da ordenação ("↑ Data" ou "N ordenações"), um chip por regra ("Tags: não contém Transferência"), **+ Filtro** e a contagem "N de M". Aparece quando há filtro ou ordenação (ou sempre, com `filterable`); o botão de filtro da barra superior mostra e esconde.
- **Cada regra** abre o próprio popover: os operadores em chips, o valor (campo, ou a lista de opções) e **Excluir filtro**. **+ Filtro** escolhe a coluna e já abre a regra nova. Regra sem valor fica só com contorno e ainda não filtra. Todas as regras valem juntas ("e"). Operadores por tipo (todos com "está vazio/não está vazio", menos a caixa): texto e relação sem opções — contém, não contém, é, não é; número e fórmula — =, ≠, &gt;, &lt;, ≥, ≤; select, status e relação com opções — é, não é (em select `multi`, lê "contém/não contém"); data — é, é antes de, é depois de; caixa — marcado, desmarcado.
- **Ordenação**: o popover "Ordenar por" alterna cada coluna entre crescente, decrescente e sem; a ordem dos cliques é a prioridade, e o cabeçalho mostra ↑/↓ (com o número quando há mais de uma).
- **Linha nova visível**: `onAddRow(preset)` recebe os valores que a linha precisa pra passar nos filtros ("Mês é Setembro" → `{ mes: "Setembro" }`) e o do grupo. Mesmo assim, se ela não passar, continua na tela até você mexer em filtro, ordenação ou busca.
- **Controlado ou não**: `filters` + `onFiltersChange` (ou só `defaultFilters`), `sorts` + `onSortsChange` (ou só `defaultSorts`).

## Menu da coluna

Clicar no cabeçalho abre o menu da coluna (233): o nome (com `onColumnsChange`), o tipo, ordenar crescente/decrescente (substitui a ordenação), filtrar (cria uma regra da coluna e abre ela), agrupar por esta propriedade, congelar/descongelar, mover pra esquerda/direita e ocultar na visão. Arrastar o cabeçalho também reordena. A coluna principal não move nem some. Coluna oculta volta pelo painel de propriedades. Excluir coluna e mudar tipo não existem: as colunas vêm de quem usa.

## Coluna congelada

A coluna principal congela por padrão (`frozen: false` desliga). `frozen: true` gruda outras colunas à esquerda ao rolar na horizontal, com borda de tinta à direita da última congelada. O gutter de seleção congela junto. Coluna congelada sempre tem largura explícita (`width`, a arrastada ou 144), porque o deslocamento de cada uma é a soma das anteriores.

## Rodapé

- **Nova página**: só aparece com `onAddRow` (no fim da tabela e de cada grupo). Pra a tabela criar a linha sozinha, use o helper exportado: `onAddRow={(preset) => onRowsChange([...rows, { ...createEmptyRow(columns), ...preset }])}`.
- **Cálculo** (sempre visível, 34): cada célula do rodapé escolhe o que calcular, por tipo — todas: contagem (linhas), não vazios, vazios, % não vazios; número e fórmula com `format`: soma, média, mediana, mín., máx., amplitude; data: mais antiga, mais recente; caixa: contagem, marcadas, desmarcadas, % marcadas. `aggregate` na coluna define o inicial. Sem cálculo, "Calcular" aparece no hover. Valores em mono, em R$ quando a coluna é moeda, sobre as linhas visíveis. A coluna principal mostra a contagem de linhas. **Mudou:** `"count"` agora conta linhas; o antigo "contar valores" é `"filled"`.

## Mobile

Abaixo de 610 de largura **do container** (container query do Tailwind v4, `@container` + `@[610px]:`, não da janela), a grade vira lista: cada linha separada por 1px, título (com ícone de página) e valor em cima, propriedades embaixo. Os chips de filtro ficam numa linha só, rolando, e um botão redondo de 55 flutua no canto pra criar. Heurística: título = coluna principal; valor à direita = primeira fórmula com `format`, senão o primeiro número; etiquetas = primeiro status + primeiro select; rodapé = primeira data + segundo select (ou primeira relação). `mobileCard: { title, value, badges, meta }` troca qualquer um por `column.id`. Cada campo do cartão edita ali mesmo, com os mesmos editores da célula (seletor, calendário, campo de texto/número, caixa). Tocar no título edita o título; abrir a linha é só pelo botão **Abrir**, sempre visível no cartão quando há `onOpenRow`.

## Controlado, sem estado próprio de dados

`DataTable` não guarda `rows` sozinho. O estado interno é só de interface: célula em edição, seleção, larguras, colunas congeladas/escondidas, agregação escolhida e, sem as props controladas, filtros e ordenação. Quem usa decide onde as linhas moram e como persistir (`onRowsChange` recebe o array inteiro já atualizado). Com `DataTableViews` + `source`, quem guarda as linhas (em cache) é a visão, e a persistência vai pela `source`. `DataTableDemo`, usado no preview acima, liga cada aba a uma API de mentira em memória (`apps/docs/components/data-table-demo.tsx`).

## Acessibilidade

- Célula de texto/número/fórmula (e relação sem opções) é um `<button>` que vira um `<input>` de verdade ao editar — funciona com Tab/Enter/Escape como qualquer campo de formulário nativo.
- O glifo da relação é um alvo separado do texto (`<a>` ou `<button>` com `aria-label="Abrir …"`), então editar e abrir são dois passos de Tab. A sobrescrita de fórmula é anunciada como "valor manual".
- O dropdown de select/status/relação fecha com `Escape` ou clicando fora, e cada opção marcada leva um `✓` (não só a cor, pra quem não distingue cor).
- Menu da coluna, ordenação, propriedades, filtros, seletor e cálculo do rodapé são `Popover` (Base UI: foco dentro, Esc fecha, foco volta pro gatilho), com itens que são `<button>` de verdade. Operadores de filtro e "Agrupar por" anunciam `aria-pressed`.
- Visões são `role="tablist"`/`role="tab"` com `aria-selected` e setas ←/→. Ferramentas ligadas anunciam `aria-pressed`. A barra de seleção é `role="toolbar"`.
- Coluna de caixa e seleção de linha usam a caixa nativa com `aria-label` (o da linha diz qual: "Selecionar Recarga de celular"). O cabeçalho de grupo anuncia `aria-expanded`.
- O painel da linha é o `@adinkra/sheet` (diálogo: foco preso, Esc fecha).
