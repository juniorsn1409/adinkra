## Como usar

```bash
bun add @adinkra/dialog
```

```tsx
import {
  Dialog,
  DialogClose,
  DialogContent,
  DialogDescription,
  DialogFooter,
  DialogHeader,
  DialogTitle,
  DialogTrigger,
} from "@adinkra/dialog";
import { Button } from "@adinkra/button";

<Dialog>
  <DialogTrigger render={<Button variant="outline" />}>Editar perfil</DialogTrigger>
  <DialogContent>
    <DialogHeader>
      <DialogTitle>Editar perfil</DialogTitle>
      <DialogDescription>Mude como seu nome aparece para a equipe.</DialogDescription>
    </DialogHeader>
    {/* campos */}
    <DialogFooter>
      <DialogClose render={<Button variant="ghost" />}>Cancelar</DialogClose>
      <Button>Salvar alterações</Button>
    </DialogFooter>
  </DialogContent>
</Dialog>;
```

Controlado, quando o diálogo precisa fechar depois de uma ação (salvar, enviar):

```tsx
const [open, setOpen] = useState(false);

<Dialog open={open} onOpenChange={setOpen}>
  …
  <Button onClick={() => { salvar(); setOpen(false); }}>Salvar</Button>
</Dialog>;
```

## Composição

- **`Dialog`** — a raiz; guarda o estado aberto/fechado.
- **`DialogTrigger`** — o botão que abre. Use `render={<Button />}` para dar a ele a aparência de um botão do sistema.
- **`DialogContent`** — o painel centralizado, com o fundo escurecido. Já inclui o portal e o botão "X" no canto.
- **`DialogHeader`**, **`DialogTitle`**, **`DialogDescription`** — o cabeçalho. O Base UI liga título e descrição ao `aria-labelledby` e ao `aria-describedby` do painel.
- **`DialogFooter`** — a fileira de ações. No celular, os botões empilham com a ação principal por cima; de `sm` pra cima, ficam em linha à direita.
- **`DialogClose`** — fecha o diálogo direto, sem lógica no meio.

## Confirmação destrutiva

O botão diz o que vai acontecer ("Excluir projeto"), não "OK". O foco inicial cai no primeiro elemento focável, aqui o "Cancelar", o lado seguro. Sem o "X" (`showClose={false}`), porque há duas saídas claras no rodapé.

## Movimento

Modal não nasce do gatilho: fica no centro da tela, então a escala parte do centro. O painel entra com fade e escala de 0,96 para 1 em 200 ms, e sai em 150 ms, com a curva `--ease-out`. O fundo só faz fade. Só `opacity` e `scale` animam. Com `prefers-reduced-motion`, a troca é instantânea.

O fundo usa `--background` translúcido: no tema claro vira um véu claro, no escuro um véu escuro. Quem separa o painel do resto é a borda de tinta.

## Acessibilidade

Vem do [Base UI](https://base-ui.com/react/components/dialog): o foco fica preso dentro do painel enquanto ele está aberto, Esc fecha, o resto da página fica inerte, e o foco volta ao gatilho ao fechar. O painel tem `role="dialog"` e `aria-modal`.

- Sempre inclua um `DialogTitle` — sem ele o leitor de tela não sabe do que se trata.
- Sempre deixe uma saída óbvia: o "X" ou um `DialogClose` no rodapé.
- Para escolher onde o foco começa, use `initialFocus` no `DialogContent`.

Para uma confirmação que não pode ser dispensada com um clique fora, use `disablePointerDismissal`. Para conteúdo que não bloqueia a página, prefira um [Popover](/components/popover); para conteúdo lateral, uma [Sheet](/components/sheet).
