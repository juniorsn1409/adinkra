## Como usar

```bash
bun add @adinkra/checkbox
```

```tsx
import { Checkbox } from "@adinkra/checkbox";

<Checkbox label="Receber o resumo semanal" />;
```

Sem `label`, use `<label htmlFor>` com o `id` (ou o `Field`, de `@adinkra/field`):

```tsx
<div style={{ display: "flex", alignItems: "center", gap: "0.625rem" }}>
  <Checkbox id="termos" />
  <label htmlFor="termos">Li e aceito os termos</label>
</div>;
```

Controlado, quando o estado precisa viver fora do componente (mesmo contrato do Switch):

```tsx
const [checked, setChecked] = useState(false);

<Checkbox checked={checked} onCheckedChange={setChecked} />;
```

### Estado indeterminado

Serve para o “selecionar tudo” quando só parte dos itens está marcada (veja o exemplo acima). Quem usa calcula `indeterminate` a partir dos itens; o clique do usuário só chama `onCheckedChange`.

```tsx
<Checkbox
  label="Todas"
  checked={todas}
  indeterminate={algumas}
  onCheckedChange={(marcar) => setMarcadas(marcar ? TODAS : [])}
/>
```

## Estados e tamanhos

Igual ao Switch e ao Input: borda de tinta + sombra dura sempre, sem o gesto de “subir no hover” (pequena demais para isso). Só a cor muda, e o ícone entra com um respiro de escala e opacidade (150ms).

## Acessibilidade

- É um `<input type="checkbox">` nativo, só com aparência própria: Espaço alterna, entra no `<form>` com `name`/`value`, e o estado indeterminado sai como `aria-checked="mixed"` sem código extra.
- Sempre dê um nome: `label`, `<label htmlFor>`, `Field` ou `aria-label`.
- `aria-invalid` pinta a borda de tomate; o texto do erro (via `Field`) diz o que fazer, nunca só a cor.
- O foco visível é o mesmo anel de 2px dos botões. `disabled` tira a caixa da ordem de tabulação.
