## Como usar

```bash
bun add @adinkra/sidebar
```

```tsx
import {
  Sidebar,
  SidebarContent,
  SidebarFooter,
  SidebarGroup,
  SidebarGroupContent,
  SidebarGroupLabel,
  SidebarHeader,
  SidebarMenu,
  SidebarMenuButton,
  SidebarMenuItem,
  SidebarProvider,
  SidebarTrigger,
} from "@adinkra/sidebar";

export default function Layout({ children }) {
  return (
    <SidebarProvider>
      <Sidebar>
        <SidebarHeader>{/* logo */}</SidebarHeader>
        <SidebarContent>
          <SidebarGroup>
            <SidebarGroupLabel>Primitivos</SidebarGroupLabel>
            <SidebarGroupContent>
              <SidebarMenu>
                <SidebarMenuItem>
                  <SidebarMenuButton isActive render={<Link href="/button" />}>
                    Button
                  </SidebarMenuButton>
                </SidebarMenuItem>
              </SidebarMenu>
            </SidebarGroupContent>
          </SidebarGroup>
        </SidebarContent>
        <SidebarFooter>
          <SidebarTrigger />
        </SidebarFooter>
      </Sidebar>
      <main>{children}</main>
    </SidebarProvider>
  );
}
```

`render` troca o `<button>` nativo por outro elemento (um `<Link>`, por exemplo) — no mesmo espírito do prop `render` do Base UI, mas sem depender dele: `@adinkra/sidebar` não tem essa dependência.

## Item ativo

Revisado contra o [sidebar do neobrutalism.dev](https://www.neobrutalism.dev/docs/sidebar): o item ativo leva um **contorno** (`outline`) de tinta ao redor, não um preenchimento em céu. Duas razões:

- `outline` não entra na caixa do elemento — ao contrário de uma borda, ele não desloca nada quando aparece. O item não "pula" ao virar ativo.
- O céu fica reservado à ação principal da tela (regra 6, `DECISOES.md`) — usá-lo aqui também competiria com ele.

## Modos de recolhimento

`collapsible="icon"` (o padrão) recolhe a sidebar para uma faixa só de ícones — o rótulo some, o ícone e o contorno do item ativo continuam; é o modo usado pela sidebar real deste site desde 17/09 (veja o preview no topo desta página, com `<SidebarRail/>` na borda) — antes disso usava `"offcanvas"`, porque nenhum item tinha ícone ainda. `collapsible="offcanvas"` recolhe até largura zero (nada fica visível) — pensado pra navegações sem ícone por item, onde uma faixa de ícones vazios não faria sentido. `collapsible="none"` deixa sempre expandida, sem nenhuma das duas opções.

  <SidebarMenuCollapsible defaultOpen>
    <SidebarMenuCollapsibleTrigger icon={<FolderIcon />}>Componentes</SidebarMenuCollapsibleTrigger>

      <SidebarMenuSubItem>

É `<details>`/`<summary>` nativo por baixo, não `useState` — abrir, fechar, teclado (Enter e Espaço) e o estado pra leitor de tela já vêm de graça do navegador. A seta gira com `group-open/collapsible:rotate-90`.

**Uma limitação conhecida:** com a sidebar recolhida a ícones, o grupo ainda abre e fecha ao clicar, mas o submenu continua escondido — ele não vira um menu flutuante. Deixar assim foi uma escolha de escopo, não um esquecimento.

## Badge e ação de item

`SidebarMenuBadge` mostra um contador (ou etiqueta curta) à direita de um item; `SidebarMenuAction` é um botão secundário no mesmo lugar — os dois ficam sobrepostos ao `SidebarMenuButton`, então o item precisa estar dentro de um `SidebarMenuItem` (ele já é `relative` por baixo, de propósito, pra isso funcionar).

```tsx
<SidebarMenuItem>
  <SidebarMenuButton>Notificações</SidebarMenuButton>
  <SidebarMenuBadge>12</SidebarMenuBadge>
</SidebarMenuItem>

<SidebarMenuItem>
  <SidebarMenuButton>Projetos</SidebarMenuButton>
  <SidebarMenuAction showOnHover aria-label="Mais opções">
    <EllipsisIcon />
  </SidebarMenuAction>
</SidebarMenuItem>
```

`showOnHover` deixa a ação invisível (`opacity-0`) até o item ganhar hover ou foco — útil quando ela é secundária e não deveria competir visualmente com o botão principal o tempo todo. Sem esse prop, a ação fica sempre visível.

## Rail

`SidebarRail` é uma faixa fina e sempre visível na borda da sidebar (desktop) que também alterna expandido/recolhido ao clicar — um alvo maior que o `SidebarTrigger`, útil quando ele não está por perto (ex.: rodapé longe do header). Renderiza como filho direto de `<Sidebar>`:

```tsx
<Sidebar>
  <SidebarHeader>{/* ... */}</SidebarHeader>
  <SidebarContent>{/* ... */}</SidebarContent>
  <SidebarRail />
</Sidebar>
```

Em mobile ele não renderiza nada — lá quem fecha a gaveta é o fundo escurecido atrás dela ou a tecla `Esc`.

## Mobile

Abaixo de 768px (o mesmo breakpoint de `useIsMobile`, exportado pelo pacote), `Sidebar` vira uma gaveta: fixa na tela, começa **fechada**, desliza com `translate-x` e ganha um fundo escurecido atrás (`bg-ink/40`) que fecha ao ser tocado. `Ctrl`/`Cmd` + `B`, `SidebarTrigger` e `Esc` (só quando a gaveta já está aberta) continuam funcionando do mesmo jeito.

Isso é automático — o mesmo `<Sidebar>` que renderiza a faixa fixa no desktop passa a renderizar a gaveta sozinho, sem nenhuma prop nova. Só é preciso garantir que exista algum `SidebarTrigger` visível em telas pequenas pra reabrir a gaveta depois de fechada (neste próprio site, ele mora numa barra que só aparece abaixo de `md`).

## Acessibilidade

- O item ativo leva `aria-current="page"` — não só o contorno visual.
- `Ctrl`/`Cmd` + `B` alterna a sidebar pelo teclado, em qualquer lugar da página.
- Recolhida a ícones, cada item ganha `title` (o `tooltip`) — quem passa o mouse ainda sabe o que cada ícone significa.
- O estado fica salvo em cookie (`adinkra_sidebar_state`), lido de novo só depois de montar no cliente — de propósito, pra manter a página estática (SSG); ver `DECISOES.md`, seção 3.
- Em mobile, o fundo escurecido atrás da gaveta é um `<button aria-label="Fechar menu">` (não uma `<div>` com `onClick`) — dá pra fechar com o teclado também, não só tocando fora.
- `Esc` fecha a gaveta mobile quando ela está aberta.
